# コード整形（`gonako format`）

`gonako format` と gonako-gui の「☰」メニュー「🧹 自動整形」は、なでしこの
プログラムを実行せずに見た目だけを整えます（#113・#118・#120）。
実装は `internal/format` で、CLI・GUIとも `format.Program` を呼びます。

```sh
gonako format main.nako3            # 整形結果を表示するだけ
gonako format main.nako3 -f         # ファイルへ書き戻す
gonako format main.nako3 --colon    # ブロックをコロン記法に書き換える
```

GUIでは「🧹 自動整形（コロン記法に変換）」が `--colon` に当たります。

## 整形の内容

| 段階 | 内容 | 例 |
|------|------|----|
| 1. 行の中身 | 演算子（`+` `-` `=` `&` `×` `≧` など）の前後に空白を1つ置く | `値＝50` → `値 = 50`、`(1+2)* 3` → `(1 + 2) × 3` |
|  | ただし両隣が全角記号（`」` `「` など）なら空白を置かない | `「あ」 ＆ 「い」` → `「あ」&「い」` |
|  | 掛け算・割り算・比較を全角の記号に揃える（`==` はそのまま） | `*` → `×`、`/` → `÷`、`>=`・`=>` → `≧`、`<=`・`=<` → `≦`、`!=`・`<>` → `≠` |
|  | 単項の `-`（負の数）の直後には空白を置かない | `A=- 1` → `A = -1` |
|  | 括弧の内側・読点やコロンの前の空白を取り、それ以外の連続した空白は1つにする | `[ 1 , 2 ]` → `[1, 2]` |
|  | 数値と記号（括弧・演算子）の全角文字を半角にする | `（1 + ２）` → `(1 + 2)` |
|  | 値と助詞の間の空白を取る | `3 を表示` → `3を表示` |
| 2. インデント | 構文木のブロック構造から、1段につき空白4つで付け直す。行末の空白を落とし、末尾の改行を1つにする | |
| 3. コロン記法（`--colon`） | `ここまで` で閉じるブロックを、行末の `:` とインデントで表す書き方に変える | 下記 |

演算子以外のトークンの間では、空白の無いところに空白を足しません。
文字列リテラル・コメント・単語の中身、行末コメントの前の空白は変えません。

コメントだけの行は、前後のコードの行のうち深い方に揃えます。
`条件分岐` は、分岐（`〇〇ならば`・`違えば`）とその `ここまで` を1段、
分岐の本文を2段深くします。

### コロン記法への変換

```nako3
もし、Aが1ならば
    「一」を表示
違えば
    「その他」を表示
ここまで
```

は、次のようになります。

```nako3
もし、Aが1ならば:
    「一」を表示
違えば:
    「その他」を表示
```

次のブロックは書き換えずに残します。

- 本文が空のブロック
- `ここまで` の行に他のコードやコメントがあるブロック
- `条件分岐` の各分岐
- `!インデント構文` などのモード指定があるファイル全体

## 意味を変えないための確認

各段階の結果をもう一度構文解析し、構文構造（`format.Structure`。位置情報と
改行を除いた構文木）が元のプログラムと一致することを確かめます。

- 段階1で一致しなければ、値と助詞の間の空白を残して再試行し、それでも
  だめなら段階1を飛ばします。
- 段階2で一致しなければ、整形を中止してエラーにします（ファイルは書き換えません）。
- 段階3でまとめて書き換えて一致しなければ、ブロックを1つずつ試し、
  一致するものだけを書き換えます。

## インデント構文・コロン記法のファイル

インデントでブロックを表すファイル（`!インデント構文` や `3回:`）では、
パーサーがインデントの戻り位置に `ここまで` を補います。補った `ここまで` と
改行は長さ0のトークンになっており（`internal/indent`）、整形処理はこれを
本物の `ここまで` の行と区別して、本文の最終行を浅くしないようにしています。
