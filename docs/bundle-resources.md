# プログラムとリソースの単一ファイル梱包（バンドル）手順

なでしこ3 Go言語版（`gonako`）では、なでしこプログラム（コンパイル済みIR）および画像やデータファイルなどのリソースフォルダを単一の実行ファイル（バイナリ）に梱包して配布できます。

作成された実行ファイルは、受け取り側の環境にGoツールチェイン、Node.js、リソースフォルダが不要で、単一のファイルだけで動作します。

---

## 1. バイナリの構造

`gonako build` は、指定されたランタイム（通常のGoバイナリ）の末尾にペイロードを追記する方式で単一ファイルを生成します。

```text
[ gonako ランタイム本体 (Goバイナリ) ][ ペイロード (ZIP) ][ フッタ (マジック + 長さ) ]
```

- **ペイロード**: コンパイル済みプログラム（JSON形式のIR）と、指定されたリソースフォルダ内の全ファイルを収録したZIPアーカイブ
- **フッタ**: バンドル識別用マジック文字列（`GONAKOBUNDLE1`）とペイロードサイズ
- **動的切り替え**: 実行ファイルは起動時に自分自身の末尾を読み込み、フッタが存在すれば同梱モードとして自動動作します。

---

## 2. 基本的なバンドル手順

### コマンド構文
```bash
gonako build <メインプログラム.nako3> [オプション]
```

### オプション一覧
| オプション | 説明 | 既定値 |
|---|---|---|
| `--out NAME` | 出力する実行ファイル名 | ソース名から自動生成（例: `app.nako3` → `app` または `app.exe`） |
| `--resource DIR` | 同梱するリソースのフォルダ | なし（プログラムのみ梱包） |
| `--runtime PATH` | 土台にするランタイムバイナリ | 実行中の `gonako` |
| `--list` | 実行ファイルに同梱されているリソースの一覧を表示 | - |

### 実行例

プログラム `かんたんゲーム.nako3` と画像フォルダ `./images` を1つの実行ファイル `かんたんゲーム` に固める場合:

```bash
gonako build かんたんゲーム.nako3 --resource ./images --out かんたんゲーム
```

## 3. なでしこプログラム側でのリソース参照

### 透明なファイルアクセス
開発中（同梱なし）と配布後（同梱あり）で、**なでしこプログラムのソースコードを変更する必要はありません**。

読み込み命令を実行すると、まずバンドル内の仮想ファイルシステム（同梱リソース）を探し、見つからなければOSの実ファイルシステムを参照します。

```nako3
# 開発中も同梱後も同じ相対パスで記述できます
データ＝「images/sub/data.txt」を開く
「データ: {データ}」と表示

画像＝「images/hero.png」をバイナリ読
「サイズ: {画像の実体}」と表示

もし、「images/sub/data.txt」が存在ならば
    「リソース読み込み成功」と表示
ここまで
```

### 対応している主な読み込み命令
- `開` / `読`
- `バイナリ読`
- `存在`
- `SJISファイル読` / `EUCファイル読`
- `DISCORDファイル送信` など

> **注意**: `保存` や `追記` などのファイル書き込み命令は、同梱リソースではなくOSの実ファイルシステムへ書き込まれます。

---

## 4. 同梱リソースの確認 (`--list`)

作成した実行ファイルにどのファイルが同梱されているか確認するには `--list` オプションを使用します。

```bash
gonako build --list かんたんゲーム
```

**出力例**:
```text
プログラム: かんたんゲーム.nako3
同梱リソース:
  images/hero.png
  images/sub/data.txt
```

## 5. 他OS向けクロスプラットフォーム梱包 (Cross-build)

ビルドを行うマシン上に各OS用のランタイムバイナリを用意しておくことで、Goツールチェインがインストールされていない環境向けにも対象OSの単一実行ファイルを生成できます。

### 手順

1. **各OS用ランタイムを用意する** (開発機側で1度ビルド):
   ```bash
   # Windows (amd64) 用
   GOOS=windows GOARCH=amd64 go build -o runtimes/gonako-windows-amd64.exe ./cmd/gonako

   # Linux (amd64) 用
   GOOS=linux GOARCH=amd64 go build -o runtimes/gonako-linux-amd64 ./cmd/gonako
   ```

2. **`--runtime` オプションを指定して梱包**:
   ```bash
   # Windows向け実行ファイル (.exe) の作成
   gonako build ゲーム.nako3 --resource ./images --runtime runtimes/gonako-windows-amd64.exe --out ゲーム.exe

   # Linux向け実行ファイルの作成
   gonako build ゲーム.nako3 --resource ./images --runtime runtimes/gonako-linux-amd64 --out ゲーム_linux
   ```

---

## 6. 注意事項・テクニック

1. **二重梱包の自動防止**:
   一度 `gonako build` で作成されたバンドル実行ファイルを `--runtime` に指定して再ビルドした場合、古いペイロードは自動的に取り除かれて新しいペイロードで上書きされます。

2. **macOSコード署名について**:
   macOS用の署名済みバイナリに対して末尾追記を行うと、署名のハッシュが変更されてコード署名が無効化されます。macOS向けに配布する場合は、`gonako build` 実行後に `codesign` コマンドで再署名を行ってください。
   ```bash
   codesign -f -s - 成果物バイナリ名
   ```
